# EditProbe 论文导读幻觉评测：首轮试跑

> 日期：2026-08-29。这个结果用于验证评测管线和筛选下一轮模型，不是多论文统计结论。

## 1. 一句话结论

在这一个论文样本上，**GPT-5.6 Luna / none 暂时给出了最好的质量—延迟折中**：机器双裁判的幻觉率区间为 0%–1.32%，关键事实召回均为 100%，生成耗时 63.2 秒；豆包已观察输出存在至少 4 条人工确认的核心事实问题，但由于产品轨道与受控 API 轨道并非同一 Prompt，不能把本轮结果解释成基础模型排行榜。

## 2. 评测设置

- 论文：EditProbe，arXiv:2603.19775，共 12 页。
- 受控轨道：六档 API 模型接收同一份带页码的 PDF 抽取文本和阅读器当前的自动总结 Prompt。
- 产品轨道：用户实际获得的豆包浏览器插件输出；记录为 `1.38.0 / undisclosed-dynamic-route`。
- 原子事实抽取：DeepSeek V4 Pro，关闭思考。
- 独立裁判：DeepSeek V4 Pro（关闭思考）和 GPT-5.6 Sol（medium）。
- 人工复核：复核全部裁判分歧、重大错误候选和数字错误候选。
- 口径：`(contradicted + not_in_source) / 可判定原子事实`；`ambiguous` 不进入分母。

## 5. 豆包输出中已实锤的问题

1. **层选择算法被改写：** 豆包称阶段 1 给每层接小回归器、按与人工评分的相关性选层；论文实际用归一化 KL divergence、Layer Discriminability Ratio 和信息熵组成 saliency score。
2. **回归任务结构错误：** 豆包称一个 MLP 同时输出四个分数；论文明确将四个目标建模为独立回归任务并分别训练。
3. **训练方式错误：** 豆包称四个任务的损失一起回传；论文明确写的是 `trained separately`。
4. **速度结论无论文证据：** 豆包称 EditProbe 比普通大模型打分快，但论文没有报告这项速度比较。

另外还有若干更依赖口径的项目，例如把总体 MOS 称作第四个人工评分、补充 AdaLoRA 的通用机制、泛化式描述普通提示打分的缺点。本报告没有把这些争议项计入保守下界。

## 6. 裁判本身也会出错

- 豆包样本的两位裁判仅有 76.19% 标签一致率：第一位只报 2 条，第二位报 12 条。
- 第一位裁判漏掉了“一头四分”和“四损失联合训练”两处核心错误。
- 第二位裁判会把合理的推理阶段描述、限定性提醒也标成 `not_in_source`。
- 原子事实抽取器有时会丢掉并列成分，例如把“只更新 AdaLoRA 和回归头”错误拆成“只更新 AdaLoRA”。
- 论文自身也有数字冲突：正文称总体 SRCC 从 0.7296 提升到 0.7795，但 Table III 的 Final Layer 是 0.7771，0.7296 对应 `w/o MLP`。模型照抄任一处都应标为 `ambiguous`，不应直接判成模型幻觉。

因此，本项目不会用单一 LLM judge 的分数宣称“某模型幻觉率就是 X%”。
